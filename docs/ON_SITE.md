# Проверка на месте: пошагово

## Что приготовить заранее

- Скопировать **всю папку**, включая четыре `.1cws.xml`, `sync1c.py`, `config.example.json` и эту инструкцию. WSDL нужны во время выполнения SOAP-запросов.
- Нужен Python 3.9+; на Windows обычно команда `py -3`, на macOS/Linux `python3`. Пакеты через pip не нужны. Если на сервере Python нет и интернета тоже, заранее взять согласованный с администратором установщик.
- Прогнать `python3 -m unittest discover -s tests -v` дома. Это проверка клиента на имитаторе, не тест настоящей 1С.
- Получить у руководителя URL публикации, способ подключения (сеть/VPN/RDP), пользователя 1С с правами чтения и подтверждение, что учебные планы в тестовой базе есть.

## 1. Выбрать место запуска и адрес

**На самом сервере через RDP:** предполагаемый адрес из материалов — `http://localhost/testun`. Если публикация существует только локально, запускать скрипт в этой RDP-сессии. База SQLite будет лежать на сервере; переносить её к себе только в согласованном порядке.

**На ноутбуке в локальной сети:** нужен адрес HTTP-сервера, например `http://192.168.200.10/testun`, только если администратор подтвердил этот адрес. `localhost` на ноутбуке указывает на ноутбук. Порт 3389 относится к RDP, его не нужно подставлять в HTTP URL.

Физическая близость к серверу не заменяет доступ к его сети. Если из браузера на сервере работает, а с ноутбука нет — проверять привязку Apache, сетевой маршрут и firewall с администратором. Для первого доказательства достаточно запуска прямо на сервере.

## 2. Создать конфигурацию

Открыть терминал **в папке проекта**.

macOS/Linux:

```sh
cp config.example.json config.json
```

Windows PowerShell:

```powershell
Copy-Item config.example.json config.json
py -3 --version
```

В `config.json` исправить только `base_url` на первом этапе. Оставить задание `soap_curriculums`. Если нужны учётные данные, ввести их в том же терминале.

macOS, стандартный zsh:

```sh
read 'ONEC_USER?Пользователь 1С: '
read -s 'ONEC_PASSWORD?Пароль 1С: '
echo
export ONEC_USER ONEC_PASSWORD
```

Linux, bash:

```sh
read -r -p 'Пользователь 1С: ' ONEC_USER
read -r -s -p 'Пароль 1С: ' ONEC_PASSWORD
echo
export ONEC_USER ONEC_PASSWORD
```

Windows PowerShell:

```powershell
$cred = Get-Credential -Message 'Учётная запись 1С'
$env:ONEC_USER = $cred.UserName
$env:ONEC_PASSWORD = $cred.GetNetworkCredential().Password
```

Не вставлять пароль в команды, файлы проекта или скриншоты. Пустой пароль допустим только если так действительно настроена тестовая учётная запись.

## 3. Проверить интерфейсы

```sh
python3 sync1c.py diagnose
```

На Windows здесь и далее заменить `python3` на `py -3`.

Команда отдельно проверит WSDL, вызов SOAP `TestConnection`, OData `$metadata`. `TestConnection: OK (...)` означает корректный SOAP-ответ; возвращаемое значение показано как есть, его смысл задаёт сервер. Это ещё не подтверждение выгрузки данных.

Если OData не работает, а SOAP отвечает — продолжать с SOAP. Если WSDL загружается, а `TestConnection` нет, проверить `sync`: у разных сервисов могут быть разные права. Если SOAP не работает, но OData возвращает сущности — использовать шаг 6.

## 4. Выполнить первую загрузку

```sh
python3 sync1c.py sync
python3 sync1c.py status
```

Ожидается `curriculums: OK, записей N`, где N > 0. Появится `data/mirror.sqlite3`. `status` должен показать успешный запуск и число активных записей.

Проверить несколько учебных планов по их названиям/идентификаторам с руководителем в интерфейсе 1С. Сохранить для отчёта время проверки, подтверждённый URL без пароля, версию Python, число записей и итог `status`. Не распространять данные стенда без согласования.

## 5. Проверить актуализацию

1. Повторить `sync`: число записей не должно увеличиться за счёт дублей.
2. Попросить руководителя изменить название одного тестового учебного плана штатно в 1С.
3. Ещё раз выполнить `sync`, проверить новое значение в `payload` SQLite. Сам клиент ничего в 1С не меняет.
4. Запустить `python3 sync1c.py watch`, убедиться, что через интервал из конфигурации появился следующий успешный запуск.
5. Остановить Ctrl+C. При кратковременной потере сети предыдущая SQLite должна остаться читаемой; ошибка будет в `runs`, после восстановления следующий цикл повторит загрузку.

Если первый и второй шаги успешны, доказано чтение и повторное сохранение. Для доказательства обновления нужна проверка реально изменённой записи, пункт 2–3.

## 6. Если нужны другие данные: OData

```sh
python3 sync1c.py entities
```

С руководителем выбрать сущность из вывода и добавить OData-задание по примеру в README. Имена сущностей не угадывать по русским названиям в пользовательском интерфейсе. Для первого теста лучше небольшой справочник; подобрать фильтр, который ограничит объём. `page_size` задаёт размер страницы, а не общий лимит записей.

Если metadata пустые, попросить администратора настроить состав стандартного интерфейса OData и права чтения. Для программной настройки в платформе есть `SetStandardODataInterfaceContent` («УстановитьСоставСтандартногоИнтерфейсаOData»); конкретное место настройки в этой конфигурации должен определить администратор. Не менять `default.vrd` вслепую — присланный файл уже содержит enable=true.

## Диагностика блокеров

| Результат | Следующее действие |
|---|---|
| Сетевая/TLS ошибка | Проверить сеть/VPN, имя и порт веб-сервера; попробовать запуск на сервере; при HTTPS проверить доверенный CA |
| HTTP 401 | Уточнить логин/пароль именно 1С и схему аутентификации; Windows/NTLM этим клиентом не поддерживается |
| HTTP 403 | Администратор проверяет права пользователя, Apache и ограничения интерфейса |
| HTTP 404 | Проверить имя `/testun`, регистр пути, публикацию соответствующего SOAP/OData endpoint |
| HTTP 500 или SOAP Fault | Администратор смотрит журнал регистрации 1С и журналы Apache по времени запроса; возможны права, лицензии, ошибка модуля или несовпадение контракта |
| XML/JSON неожиданного формата | Убедиться, что URL не возвращает страницу входа/HTML; сверить текущий WSDL с присланным |
| Нет EntitySet | Настроить состав OData; проверить под нужным пользователем |
| Пустая выборка | Проверить наличие данных, фильтр и права; не включать allow_empty до выяснения причины |
| Дубли ключей / max_pages | Сузить выборку, проверить ключи и изменения источника во время выгрузки; старые данные сохранены |

Если запуск на сервере успешно читает хотя бы учебные планы, отсутствие доступа с ноутбука — инфраструктурное ограничение, а не невозможность диплома. Можно держать загрузчик рядом с 1С и отдельно согласовать доступ к своей БД.

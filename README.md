# Проверка интеграции с 1С и периодическая актуализация SQLite

Рабочий прототип на Python 3.9+ без внешних зависимостей. Исходные файлы руководителя сохранены без изменений. Начните с [инструкции выезда](docs/ON_SITE.md).

**Реальное подключение к стенду пока не подтверждено.** Адрес веб-публикации и учётные данные не предоставлены. WSDL описывает контракт, но не доказывает доступность сервера, права пользователя или наличие данных.

## Что найдено в материалах

- На скриншоте: «1С:Университет ПРОФ, редакция 2.3», веб-публикация `/testun`, Apache 2.4.
- `default.vrd`: база `testun` на сервере кластера `KMCno1C`, включены SOAP и стандартный OData. Имя сервера кластера не обязательно совпадает с адресом веб-сервера.
- WSDL указывают `http://localhost/testun/ws/...`. Это localhost компьютера, на котором работает веб-сервер.
- `192.168.200.10:3389` на скриншоте — адрес RDP. Это кандидат для проверки, а не подтверждённый HTTP endpoint.
- `study.1cws.xml`: `GetAllCurriculums()` возвращает список учебных планов с `CurriculumId`, `CurriculumName`, `CurriculumRef`, специальностью, формой обучения, подразделением и уровнем образования. Метод не требует параметров SOAP, но может требовать HTTP-аутентификацию и права.
- `webapplication.1cws.xml`: `TestConnection()` для диагностики SOAP.
- Есть и изменяющие данные методы. Клиент допускает только три явно перечисленных метода чтения; произвольные SOAP-операции не вызывает.

## Быстрый старт без стенда

```sh
python3 --version
python3 -m unittest discover -s tests -v
```

Тесты запускают временный HTTP-сервер только на `127.0.0.1` и используют временную SQLite. Они не обращаются к стенду и не требуют пароля. Проверяют реальную HTTP-цепочку с искусственными ответами, SOAPAction из присланного WSDL, Basic auth, OData с ограничением размера страницы и nextLink, повторную загрузку, изменения и исчезновение записей, защиту данных при ошибках, пустых ответах и дублях.

## Настройка и запуск

```sh
cp config.example.json config.json
# Измените base_url в config.json на подтверждённый адрес публикации.
python3 sync1c.py diagnose
python3 sync1c.py sync
python3 sync1c.py status
python3 sync1c.py watch
```

Последняя команда выполняет загрузку сразу и затем через `interval_seconds` после завершения предыдущего цикла; остановка Ctrl+C. Ошибка загрузки фиксируется, следующий цикл повторит попытку. Код возврата `sync`: 0 — все задания успешны, 1 — ошибка. `diagnose` возвращает 1, если любой проверяемый интерфейс недоступен: SOAP при этом может работать даже при выключенном OData.

Пароль не записывается в конфигурацию. Если нужна аутентификация, задайте `ONEC_USER` и `ONEC_PASSWORD` в окружении процесса; безопасный интерактивный ввод приведён в инструкции выезда. Поддерживается HTTP Basic, включая анонимный доступ без этих переменных. NTLM/Kerberos, формы входа и внешние токены не реализованы. При иной схеме аутентификации нужен отдельный адаптер или согласованная с администратором настройка публикации.

Для HTTPS можно указать `"ca_file": "/path/to/internal-ca.pem"`. Проверка TLS включена. Системные HTTP-прокси не используются: запросы идут напрямую к указанному серверу. HTTP redirect намеренно отклоняется, чтобы не передавать учётные данные на другой адрес; укажите конечный URL. При Basic поверх HTTP пароль не шифруется транспортом: предпочтительны HTTPS либо запуск прямо на сервере через localhost по согласованной схеме.

## Выбор данных через OData

Сначала узнайте **реальные** имена опубликованных сущностей и их ключи:

```sh
python3 sync1c.py entities
```

Затем добавьте задание в `jobs` (имя ниже условное; замените на существующее из вывода `entities`):

```json
{
  "name": "selected_catalog",
  "kind": "odata",
  "entity": "Catalog_ИмяИзMetadata",
  "page_size": 200,
  "max_pages": 10000,
  "select": ["Description", "Code"],
  "filter": "DeletionMark eq false",
  "allow_empty": false
}
```

`select` и `filter` необязательны; имена полей должны существовать в конкретной конфигурации. Ключевые поля добавляются к `$select` автоматически из `$metadata`, поддерживаются составные ключи. Весь JSON каждой записи, включая вложенные данные, сохраняется в SQLite. Клиент следует nextLink в пределах этой же публикации либо использует `$skip/$top` с сортировкой по ключу; читает до пустой страницы. Лимит страниц, повторная ссылка, отсутствующий ключ или дубликат прерывают сохранение всего задания.

Отметка «Публиковать стандартный интерфейс OData» сама по себе недостаточна: требуется состав объектов, доступных через интерфейс, и права пользователя. Это описано в [официальной инструкции 1Ci](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Integration/How_to_use_the_oData_protocol_when_publishing_an_infobase_to_web_server/). Синтаксис запросов и примеры JSON: [документация 1С:Фреш](https://1cfresh.com/articles/data_odata). Возможности конкретной конфигурации проверяются на стенде.

## Как устроена своя БД

Файл по умолчанию: `data/mirror.sqlite3`, относительно файла конфигурации.

- `records`: источник/задание (`dataset`), ключ (`record_key`), исходная запись (`payload`, JSON), `active`, времена изменения содержимого и последнего получения (UTC).
- `current_records`: представление с `active=1` для текущей выборки.
- `runs`: история успешных и неудачных запусков с количеством строк и краткой ошибкой без тел ответа и паролей.

Данные сначала полностью читаются и проверяются, затем одно задание обновляет свою выборку в SQLite одной транзакцией. Повторные записи обновляются по ключу. Записи, отсутствующие в новой выборке, помечаются `active=0`, физически не удаляются. Это означает «не вошла в текущую выборку», а не обязательно удаление в 1С: причиной могут быть фильтр или изменённые права.

Пустая выборка по умолчанию считается ошибкой и не выключает все старые записи. Если пустой результат действительно допустим, установите `allow_empty: true`. Частичное сокращение данных из-за изменения прав автоматически не распознаётся.

Идентификатор `dataset` содержит хеш URL и конфигурации задания: смена сервера, фильтра, полей или даже размера страницы создаёт отдельный набор. Старые наборы сохраняются; при чтении обязательно выбирайте нужный `dataset` из `status`, не объединяйте их вслепую.

Пример просмотра без дополнительных программ:

```sh
python3 -c "import sqlite3; c=sqlite3.connect('data/mirror.sqlite3'); print(c.execute('SELECT dataset,record_key,payload FROM current_records LIMIT 5').fetchall())"
```

Это прототип полного периодического снимка, а не инкрементальная репликация и не копия всей БД 1С. История версий самих записей не ведётся. Между страницами источник может измениться: сортировка и проверка дублей уменьшают риск, но не гарантируют согласованный снимок на стороне 1С. Для больших объёмов и строгой согласованности потребуется согласовать с администратором механизм изменений/выгрузку со снимком. Все записи одного задания временно находятся в памяти; один HTTP-ответ ограничен 64 MiB.

Запускайте **один процесс загрузки на файл БД**; параллельный ручной запуск и `watch` не поддерживаются. Задания независимы: успех одного не откатывается из-за ошибки другого. Транзакция данных и запись истории запусков раздельные: при аварийном завершении после commit данные могут обновиться без записи в `runs`. Для дипломного промышленного варианта стоит добавить блокировку экземпляра, строгий журнал запусков и наблюдаемость.

`watch` работает, пока процесс и компьютер включены. Для постоянной работы его нужно разместить на компьютере с доступом к стенду (например, запустить через планировщик ОС), либо запускать однократный `sync` по расписанию без пересечения запусков. Отдельный веб-сервер/API этому прототипу не нужен.

## Реальные блокеры

1. Нет подтверждённого URL веб-публикации и маршрута к нему: локальная сеть, VPN либо запуск на сервере.
2. Нет логина/пароля и подтверждённых прав чтения. Успешный вход по RDP не означает доступ в 1С.
3. Неизвестно, включены ли нужные объекты в состав OData. SOAP учебных планов — независимый запасной путь.
4. Не согласован предмет выгрузки для диплома. Сейчас реализованы учебные планы и настраиваемые выборки OData; произвольный SQL/запрос языка 1С через эти интерфейсы не отправляется.
5. Неизвестно, заполнена ли тестовая база. Пустой список не доказывает невозможность интеграции.

По предоставленным контрактам технический путь есть. Решение о смене темы разумно принимать после проверки сети, аутентификации и хотя бы одной реальной выгрузки, а не на основании отсутствия доступа из дома.
